# Pages site

<!-- markdownlint-disable MD013 -->

**Live:** https://ocha-dap.github.io/ds-aa-bfa-drought/

Landing page plus per-analysis pages, using the team's Pages template (HDX v2 tokens,
particle hero, cards — lineage `ds-storm-impact-harmonisation` → `ds-geospatial-impact-estimates`
→ `ds-seas5-skill`). There is no build step: `.github/workflows/deploy-pages.yml` copies
`pages/` to the site root on push to `main` touching `pages/**`, or on
manual dispatch.

## Adding a page

Create a directory under `pages/` with an `index.html`, paste the back-to-home snippet as the
first element in `<body>` (copy it from an existing page), and add a card to `pages/index.html`.
Keep source documents out of the repo — the repo is public; summarise, don't republish.

## The September 2026 external-sources comparison

`pages/external-sources-sep-2026/index.html` is hand-authored HTML. The two inline SVG
heatmaps are generated from the JRC ASAP `warnings_l2_ts` archive filtered to the four AOI
provinces (asap2 ids 3820, 3824, 3825, 3827). To refresh after a new dekad:

```bash
curl -sL -o /tmp/warnings_l2_ts.zip https://agricultural-production-hotspots.ec.europa.eu/files/warnings_l2_ts.zip
unzip -p /tmp/warnings_l2_ts.zip | grep -E '^(asap0_id|219;[0-9]+;(3820|3824|3825|3827);)' > /tmp/aoi.csv
```

then re-run the figure script (see the page's footer for the data vintage) and paste the SVGs
back into the HTML in place of the existing `<svg>` blocks.

## The detrended-biomass analysis

`pages/biomass-detrended/index.html` is hand-authored HTML with inline SVG figures generated by
`scripts/detrend_biomass_figs.py` from `scripts/detrend_biomass_analysis.py`. Inputs: ASAP's
per-province indicator-statistics export (GAUL level 2, `country_id=219`; endpoint documented in
`OCHA-DAP/ds-asap-trends`) for zFPARc cropland/rangeland, plus the ASAP `warnings_l2_ts` archive
filtered to the four provinces (see above). Run the analysis script with the scratch directory
holding `asap_bfa/*.csv` and `aoi.csv`, then the figure script, then paste the SVGs into the page.

## The heat-and-drought analysis

`pages/temperature/index.html` is hand-authored HTML with inline SVG figures from
`scripts/temperature_analysis.py` (tables) and `scripts/temperature_figs.py` (figures). Inputs: the
same ASAP province export as above plus temperature (variable 140), rainfall (10), WSI (160) and
SPI-3 (40); the SEAS5 forecast comes from the Copernicus Climate Data Store via `scripts/cds_t2m.py`
(needs a `~/.cdsapirc` with the CDS URL, not the EWDS one).

## The heat-and-impact analysis

`pages/heat-and-impact/index.html` is hand-authored HTML with inline SVG figures from
`scripts/impact_figs.py`, computed by `scripts/impact_analysis.py`. The "at a glance" scatter grid
(production, yield and impact seasons against each indicator, framework provinces and all provinces) is
`scripts/impact_scatter_grid.py`, run on the same scratch directory after `impact_analysis.py`; it writes
`grid_aoi.svg` and `grid_nat.svg` to paste into the page. Since November 2026 the analysis uses ASAP's
renumbered province ids (country_id=17); the September 2026 figures used the old ids (219) and ASAP's
rainfall before its October revision, see the dated note on the page. Inputs beyond the ASAP export:
FAOSTAT production from HDX (`bfa-faostat-crops-livestock-production`), the EM-DAT blob snapshot
(`ocha_stratus.emdat`), and the team dev database (`aa.cerf_allocation` + `aa.cerf_supplement`,
`ipc.population`, `fewsnet.classification`); the pulls are one-off queries recorded in the page's
source note, not scripted here. The impact-season dating table is in the analysis script.

## The ASAP warning explorer

`pages/asap-explorer/` is an interactive page: `explorer.js` evaluates the trigger rule in the browser
from `data.json`, which holds every province's dekadal ASAP cropland and rangeland warning codes
(2001–2026), province millet and sorghum yields from the FEWS NET Data Warehouse, national yield and
production from FAOSTAT, and the drought impact records (the same dating as the heat-and-impact page).
To refresh after a new dekad or a new year of crop statistics, download the four inputs listed in the
docstring of `scripts/asap_explorer/build_data.py`, then:

```bash
uv run --with pandas --with geopandas --with pyogrio --with "shapely>=2.1" python scripts/asap_explorer/build_data.py \
    warnings_l2_ts.zip bf_crop.csv bfa_faostat.csv bfa_adm2.shp pages/asap-explorer/data.json
node scripts/asap_explorer/check_rules.js
```

The page has a map by season (2020 COD-AB provinces, simplified by `build_map` in the same script, which
the temperature explorer's build reuses): each province coloured by its highest ASAP warning level over
the chosen dekads (or at one dekad) under the land-cover setting, outlined when it meets the warning
condition, with a panel saying whether the season reached the threshold. It links to the JRC's own
ASAP Warning Explorer.

The build fails loudly if ASAP changes Burkina Faso's country id again (it moved from 219 to 17
between March and November 2026), adds a warning code, or if the 45 provinces no longer match
between ASAP and FEWS NET. `check_rules.js` re-derives known results (the framework rule on its four
provinces gives 2002, 2004, 2006, 2009, 2011; national counts match values computed separately with
pandas from the November 2026 archive). The expected values are tied to that archive and need
updating when ASAP revises past dekads. Settings are kept in the URL query string, so a view can be shared as a link.
When `explorer.js` changes, bump the `?v=` on its `<script>` tag in `index.html` so browsers do not pair a
cached old script with the new page; `data.json` is always revalidated.

The page is in English and French (toggle at the top right; `?lang=fr` opens it in French; the choice is
kept in `localStorage` under `aa-lang`, the key the team's other bilingual sites use). Static text
carries both languages as `.lv-en` / `.lv-fr` elements switched by CSS; `<option>`s and `aria-label`s
carry a `data-fr` / `data-aria-fr` attribute; text built in `explorer.js` goes through `t(en, fr)` and is
re-rendered on a switch. The impact records' French labels are in `build_data.py` (`label_fr`,
`recorded_fr`). French terms follow the BFA framework document and the glossary in the KB
(`docs/I18N.md`): *alerte de niveau 3 (bilan hydrique + biomasse)*, *zones agricoles / de pâturage*,
*décade*, *seuil*, *période de retour*. Numbers keep the decimal point in both languages. The CSV
download stays in English.

## The temperature explorer

`pages/temperature-explorer/` follows the ASAP explorer's pattern (same layout, bilingual mechanism, impact
records and province yields) for the temperature indicator of the heat-and-impact page: ASAP temperature
over cropland (variable 140, in-season cropland mask, ECMWF), averaged over the chosen dekads, minus the
province's own Theil–Sen trend fitted over 1989–2025 (line through the mean of the fit years, as in
`scripts/impact_analysis.py`). `data.json` stores the dekadal temperatures for dekads 17–29 (the span with
data for every province in every season, 1989–2026) plus the simplified 2020 COD-AB province boundaries;
the window mean, the trend and the anomaly are computed in the browser. National FAOSTAT yield and
production use a 1989–2023 trend here (2001–2023 on the ASAP explorer). To refresh:

```bash
uv run --with pandas --with geopandas --with pyogrio --with "shapely>=2.1" python scripts/temperature_explorer/build_data.py \
    temp_crop.csv bf_crop.csv bfa_faostat.csv bfa_adm2.shp pages/temperature-explorer/data.json
node scripts/temperature_explorer/check_rules.js
```

The download commands are in the script's docstring; the province list comes from
`pages/asap-explorer/data.json`, so build the ASAP explorer first. `check_rules.js` reproduces the
four-province July–September anomalies and national counts computed separately with pandas from the
November 2026 export; update the expected values when ASAP revises the series.

## The HNRP 2027 baseline (password-protected)

`pages/hnrp-2027/` holds only a gate page and `page.enc`, the AES-256-GCM-encrypted page
(PBKDF2-SHA256, 300 000 iterations; decrypted in the browser). The plaintext page, its CSV/XLSX
downloads and the work files are never committed: build them outside the repo with
`scripts/hnrp_2027/` (see its README) and copy only the encrypted `page.enc` here.
